## Outcome

The requested paired Spike instructions-per-element comparison was **not produced**. Existing artifacts provide (1) RV64 Spike outputs for original probes and (2) numerical replay/rewrites for exact recipes, but no matched exact-recipe RV64 ELF/run for the same op input and shape. The original probe logs report a `CYCLES` total that includes the VM runtime, module setup and invocation; they do not expose per-op retired instruction counts. The exact-recipe replay artifacts are compiled/run on CPU and do not supply a comparable Spike instruction counter. Consequently no cost delta or whole-model “exactness tax” can be calculated from this evidence. This is an evidence limitation, not a zero-cost finding.

The fixed numerical gate remains unchanged: SmolVLA per-element `atol=rtol=1e-3` from `runs/smolvla-numerics/SPEC.md`; TinyLlama `atol=rtol=1e-3` from `runs/tinyllama2/REPORT.md`. Local bitwise counts below are stricter diagnostics, not replacement acceptance gates.

## Whole-model implication

No numeric whole-model instruction estimate attributable to exactness recipes is justified without paired per-op instruction deltas and exact dispatch element counts. Existing trace context is useful for prioritization only: ResNet has 57.75% invoke scalar requantization epilogues, 14.3% tiny M=49 dispatches, 8% scalar im2col/packing and 6.2% maxpool+quantize (root `REPORT.md`, summarized input); TinyLlama has 81.5% in scalar FP32 lm_head and 8% scalar elementwise (root report); SmolVLA scalar elementwise is dominant, with `runs/probeSPL/scaled-dispatches.json` estimating ~2.802T instructions in elementwise_1572864 and ~408.58G in elementwise_broadcast_3072x64 under its altered one-workgroup scaling diagnostic. None of those totals separates exactness-recipe work from inherent lowering. ResNet quantization epilogues are likely a high-value target to pair; this is prioritization, not a measured classification of their fraction due to exactness.

## Why this deliverable is incomplete

A valid paired run requires, for every class, the same dependency-closed op slice, exact same input bytes/shape and ABI, two VMFBs generated from the snapshot compiler with a clearly identified baseline and exact recipe, Spike execution with an explicit `instret` counter or reliable retired-instruction trace, normalization by the number of returned elements, and reference comparisons against PyTorch at the unchanged gate. Saved `probeP1/P2/P3` probes provide relevant model slices and Spike infrastructure, but do not provide this pair for each class. The fixE/fixG/fixB recipe artifacts do not preserve a parallel RV64/Spike artifact for each op. No unsupported conversion between wall time/cycles and instructions was made.

Compiler provenance available in the reports is the bundled Merlin-IREE snapshot, LLVM 23.0.0git, with patched fixW/fixJ numerical modes used in several probes; details are in each source report's command records and `runs/fixE/versions.json`, `runs/probeP2/*/commands.jsonl`. All pre-existing logs and outputs remain untouched.
