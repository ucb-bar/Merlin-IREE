# attU: snapshot-only IREE and Merlin Gemmini ownership audit

Updated 2026-10-27 UTC. Read-only source/report audit; no compile, runtime, build, network, or source mutation. All classifications below mean **where the deciding code is in this supplied snapshot**: U = `third_party/iree_bar` / bundled torch-mlir; M = Merlin compiler/plugin/runtime/build configuration; O = our export, pipeline, flags, patches, or exactness constraints; H = configured target/bitstream. Evidence type is marked measured or inferred. Snapshot IREE commit recorded in `runs/REPORT.md`: `0f39f82b8364007da5c9dcc7ee2825812f9441ed`.

## Which component decides what

| Decision | Owner in snapshot and evidence | Controls and consequence |
|---|---|---|
| Dispatch creation/fusion | **U.** IREE global optimization and dispatch creation form/fuse executable dispatches. Merlin's post-global-opt hook attaches compilation info to eligible ops after this process; it does not itself fuse general attention or scalar epilogues across dispatches. The plugin hook and downstream custom pipeline are visible in `iree-latest/source/Merlin-IREE/compiler/src/merlin/Dialect/Gemmini/Transforms/AttachCompilationInfo.cpp:11-26,157-180,290-310`. | IREE global-opt/dispatch pipeline options and graph shape control formation. `--iree-gemmini-enable` activates Merlin's post-global-opt recovery, not general graph fusion (`compiler/plugins/target/Gemmini/GemminiOptions.cpp:7-23`). Ownership is source-inferred; no alternate dispatch pipeline was run. |
| Which operations are tagged for Gemmini | **M.** The hook accepts named matmul and contraction generic ops only when element-type predicates pass, plus recognized Conv2D generics and one matmul-like generic (`AttachCompilationInfo.cpp:59-118,307-355`). Ordinary elementwise/fill ops do not qualify. No single shape threshold defines eligibility; shape affects partitioning and tiling. | `--iree-gemmini-enable`, `--iree-gemmini-enable-matmul`, `--iree-gemmini-enable-fp8-matmul`, and `--iree-gemmini-enable-conv2d`; type predicates and rewrite patterns remain the decisive gates (`GemminiOptions.cpp:10-38`). |
| Tile sizes | **U + M.** Merlin attaches an IREE distribution tile `[DIM,0,0]`, which makes upstream distribution split M into workgroups; Merlin's tile/ISA lowering chooses the inner Gemmini tile and command loops (`AttachCompilationInfo.cpp:181-207,212-257`). Upstream data-tiling hints/selection live separately under `third_party/iree_bar/compiler/src/iree/compiler/DispatchCreation/AnnotateDataTilingHints.cpp`; they do not select Gemmini's inner tile. | `--iree-gemmini-dim` (default 16), `--iree-gemmini-tile-{m,n,k}`, dataflow, loop-WS, and hardware descriptors (`GemminiOptions.cpp:41-86,116-124`). LLVMCPU data-tiling options affect fallback CPU codegen. The DIM workgroup cap and inner-tile algorithm are Merlin decisions, not generic upstream tiling policy. |
| Requantization / epilogue | **M + U.** Merlin recognizes a limited requantize/clamp form and builds Gemmini ops (`ConvertToGemmini.cpp:592-744`). Unsupported arithmetic stays in the dispatch and uses ordinary IREE CPU lowering. Merlin preprocessing includes a narrow maxpool/QDQ cancellation (`Preprocess.cpp:11-22,78-118`); upstream fusion/dispatch formation determines whether adjacent arithmetic is in the same dispatch. | `--iree-gemmini-enable-requantize` and `--iree-gemmini-enable-clamp` (`GemminiOptions.cpp:33-38`); exact pattern/constant restrictions live in Merlin. CPU fallback is U. |
| Convolution and im2col | **U transform; M recovery.** Snapshot IREE's `iree-global-opt-convert-conv2d-to-img2col` pass converts conv into packing generic plus matmul (`third_party/iree_bar/compiler/src/iree/compiler/GlobalOptimization/Passes.td:17-19`; `ConvertConv2DToImg2Col.cpp:49-67,145-200`). Merlin also has a Conv2D generic path, and its source explicitly says this path requires removing the upstream img2col transform so convolution survives in the expected form (`AttachCompilationInfo.cpp:49-55,334-345`). | IREE pass flag/pipeline controls im2col. Merlin `--iree-gemmini-enable-conv2d` controls recovery. Our historical ResNet recipe includes preprocessing passes that our model compile record omitted: **O** when that recipe is the intended route; see historical example and `runs/optAnalysis/REPORT.md`. |
| FP32 matmul on RV64 | **U fallback + H target.** Without eligible Merlin FP8/other supported path, FP32 is LLVMCPU codegen. Current FireSim target configuration is RV64GC; it provides no RVV vector ISA to Rocket hart 0 (`build_tools/hardware/firesim_shuttle_gemmini_opu.yaml:4-6`). The exact fallback assembly/throughput is a compiler+target result, not proved by this source audit. | LLVMCPU target triple/features and data-tiling/ukernel options in compile flags; Merlin experimental FP8 flag only applies to FP8 types. Gemmini INT8 does not absorb FP32 head/attention. The configured OPU is on the other hart and is not assumed to execute these model ops. |
| Softmax / attention | **U dispatch/fallback; M lacks general conversion.** Attention lowers to contractions plus softmax/elementwise ops; the Gemmini matcher covers eligible contractions, not a general attention/softmax region (`AttachCompilationInfo.cpp:307-355`; no attention/softmax option in `GemminiOptions.cpp:7-124`). Fusion depends on upstream pipeline and graph form. | Upstream dispatch/fusion and LLVMCPU flags; no Merlin softmax/attention enable flag in this snapshot. Attribution is inferred from source, not a controlled same-dispatch comparison. |
| Runtime command path | **M.** Merlin lowering emits Gemmini intrinsic/custom command operations or optional MMIO lowering; snapshot runtime includes the Gemmini counter helper but the requested `runtime/plugins/merlin-samples` directory is absent. | `--iree-gemmini-command-issue`, `--iree-gemmini-mmio-base`, loop-WS and hardware descriptor must agree (`GemminiOptions.cpp:99-124`). Runtime helper: `third_party/iree_bar/runtime/src/iree/hal/local/loaders/merlin_gemmini_counter.h`. |

## Genuine U limitations, M gaps, O flaws, H limits

**U, supported by this snapshot:** generic IREE dispatch formation/fusion and LLVMCPU fallback own operations not selected by a target-specific codegen pipeline. This is an ownership fact, not proof that upstream CPU codegen is defective or that the same dispatch would have identical performance without Merlin. The snapshot Torch-MLIR TorchToLinalg GELU lowering has a semantic constant issue documented and numerically bisected in `runs/smolvla-numerics/SPEC.md`; source is `third_party/iree_bar/third_party/torch-mlir/lib/Conversion/TorchToLinalg/Uncategorized.cpp:746`. That is a genuine snapshot U correctness issue, but not one of the measured cycle sinks. The snapshot includes upstream im2col and data-tiling pass sources; availability does not mean our compile recipe invoked them. **Newer upstream status: not investigated**, per scope rule; no claims about fixes, issues, PRs, or stock IREE.

**M:** Gemmini matching is deliberately bounded by op kind and element-type predicates (`AttachCompilationInfo.cpp:59-118,307-355`). General softmax/attention, arbitrary elementwise work and unsupported exact QDQ forms remain CPU work. Requantize/clamp, convolution recovery, workgroup DIM capping, tile selection, address generation and ISA lowering are Merlin implementations (`ConvertToGemmini.cpp`, `LowerTileToISA.cpp`, `LowerIntrToMmio.cpp`). The user's fixD/fixK/fixW notes in local run reports document concrete Merlin tile/stack/address workarounds. These are not U issues.

**O:** ResNet's historical compile recipe applied conv layout/quantized-conv/img2col preprocessing, whereas our compile path omitted executable preprocessing hooks (see `historical_examples/merlin_iree_resnet50_int8_opt_20260905/` and `runs/optAnalysis/REPORT.md`). This is a usage gap where that transformed pattern is required; source also documents the opposite Conv2D route when img2col is removed. TinyLlama intentionally leaves its FP32 lm_head and attention in floating point (`runs/tinyllama2/REPORT.md`). SmolVLA's export and fixed exactness constraints are recorded in `runs/smolvla-numerics/SPEC.md`; failures there must not be reclassified as accelerator limitations.

**H:** FireSim configuration is a DIM16 Gemmini with RV64GC Rocket harts and a separate OPU hart, as configured in `build_tools/hardware/firesim_shuttle_gemmini_opu.yaml`. INT8 array capability does not accelerate unconverted FP32 ops. DDR3/FR-FCFS and LLC can contribute to total timing, but `runs/optAnalysis/REPORT.md` reports no DRAM, LLC-miss, DMA-byte or Gemmini-busy counters; do not attribute measured residual cycles to those hardware causes. No F2 result was produced by this audit.
